4. 队名与内容须遵守行为准则（第 8 节）。

## 3. 提交内容

1. **结果文件。** 列为 `decision_id, slot_id, action, tile_id, program, request_id, reason` 的 `decisions.csv`，由你在天气公开的场景上本地运行智能体生成。由冻结的评分器即时评分。
2. **智能体程序包。** 根目录（或唯一顶层文件夹）含入口脚本 `minimal_agent.py`、`agent.py` 或 `main.py` 的 `.zip`，可选 `requirements.txt` 与 `.env`，以及脚本导入的其他文件。不依赖其他文件时也接受单个 `.py`。平台通过 `participant-agent-protocol-v1` 在该阶段的每个场景上运行程序包，并对提交的决策评分。比赛的天气、预报与事件永不提供下载。
3. 文件不超过 20 MB。压缩包不超过 2,000 个文件、解压后不超过 50 MB。拒绝符号链接与越出压缩包根目录的路径。

## 4. 平台运行

1. 运行时：沙箱中的 Python 3.12，工作目录为程序包目录。`requirements.txt` 在时钟开始前装进每次运行独立的虚拟环境；`.env` 只注入智能体环境。允许联网，智能体可用自己的密钥或赞助额度调用模型 API。
2. 计时：每个场景一个全局时钟（`global_wallclock_seconds`，按场景公布），从初始发布后开始并覆盖全部决策；没有单次决策超时。初始化另有 30 秒预算。时钟到期时进程被终止，已提交的动作连同终局惩罚一起评分。
3. 进程退出、回复的不是 `action` 为 `observe` 或 `wait` 的 `decision_response`、或初始化失败，均以 `agent_error` / `agent_initialization_error` 结束运行。已提交的动作仍然评分；没有任何提交动作的运行承担全部终局惩罚。
4. 智能体只收到已发布的快照：当前时隙天气、带有效条件的候选天区、已发布的预报与请求，以及自身进度。它永远不会收到未来天气或事件列表。
5. 试图读取其他队伍数据、逃逸沙箱、访问场景文件、篡改评分器或得分文件、或故意耗尽平台资源，将被取消资格。

## 5. 评分

得分由公开的 `scoring_core.py`（schema `challenge-score-v3`）按 `config/score_config.json` 中的常数计算。概要：

1. 时间是真实夜晚上的 900 秒时隙日历。`observe` 从游标起持续天区的 `nominal_exptime_seconds`，可跨时隙并切分为分段；`wait` 消耗当前时隙剩余时间。
2. 对**完成**曝光的每个分段，在分段中点：
   `A = min(instrument_efficiency · transparency · sky_quality / (seeing_arcsec · airmass), 3.0)`，`combined = A · lunar_quality_factor`，
   `base = V_tile · (segment_seconds / nominal_exptime_seconds) · combined`，其中 `V_tile` 为天区目标的 `science_weight` 之和；
   `bonus = base · B[program]`，`B = {DARK 0.25, BRIGHT 0.15, BACKUP 0.08}`，仅当决策项目等于 `combined` 所对应的区间（DARK ≥ 0.65，BRIGHT ≥ 0.40，否则 BACKUP）时支付。
3. `total = base_science + program_bonus + request_reward − unsafe_observation − invalid_action − avoidable_wait − required_miss − flexible_shortfall − request_miss`：每次不安全观测（圆顶关闭时观测）2000；每次无效动作（未知天区/时隙/项目、重复天区、窗口之外、错误请求标注、在天区落下或夜晚结束前无法完成的曝光、过期决策）100；每秒可避免等待 0.001；每个未完成的 REQUIRED 天区 1000；每个分区少于配额 4 个的 FLEXIBLE 天区每个 100；到期请求每个所需天区 190（完成则每个所需天区奖励 140）。
4. 只有完成的曝光计分。被关闭天气中断的曝光不计分也不受罚；被几何或夜晚结束中断的曝光不计分并记为无效动作。每个天区只获得一次普通分；带请求标注的复访只计入请求。
5. 终局惩罚适用于每次运行，包括被时钟或智能体错误截断的运行。可行机会少于所需天区数的到期请求予以免责。
6. 完成度（已完成天区 ÷ 天区数）与各分区 FLEXIBLE 缺额显示在榜单上；它们通过终局惩罚进入得分。
7. 阶段含多个场景时，提交得分为各场景得分的算术平均。只有所有场景都完成评分的提交才计入。

## 6. 排名、同分与核验

1. 每队取该阶段最佳的已评分、未被排除的提交。按得分降序排名；严格同分时先提交者在前。
2. 线上比赛榜单实时更新。主办方可在最后几小时封榜，并在核验后公布最终排名。
3. 确认奖项前，主办方会重跑前列提交，并可要求前列队伍提供程序包与简短方法说明。无法在平台复现的结果将被移除。平台运行受全局时钟约束，重跑使用相同时钟与场景；提交动作数量的少量差异属正常，不作为申诉依据。
4. 若发现评分器缺陷，主办方可重新评分。评分器或常数的任何变更都会带版本号公告，并适用于该阶段全部提交。线上比赛开始前，当前常数为主办方的临时校准值。
